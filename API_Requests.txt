BASE URL
- http://localhost:8080

COMMON HEADERS
- Content-Type: application/json
- Authorization: Bearer <JWT>   (only for protected endpoints)

AUTHENTICATION
1) Register (POST)
URL: /auth/register
Headers: Content-Type: application/json
Body:
{
  "username": "pepsi",
  "email": "pepsi@max.com",
  "password": "parola123"
}
server assigns ROLE_USER automatically.

2) Verify account (GET)
URL: /auth/verify?token=<tokenFromEmail>
Headers: (none)
Body: (none)

3) Login (POST)
URL: /auth/login
Headers: Content-Type: application/json
Body:
{
  "username": "pepsi",
  "password": "parola123"
}
Response JSON:
{
  "token": "eyJhbGciOiJIUzI1NiIsInR..."
}

USER PROFILE
1) Get my profile (GET)
URL: /api/users/me
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON:
{
  "id": 12,
  "username": "pepsi",
  "email": "pepsi@max.com"
}

2) List my skills (GET)
URL: /api/users/me/skills
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON:
["Java", "Spring Boot", "Docker"]

3) Add skills (POST)
URL: /api/users/me/skills
Headers:
- Authorization: Bearer <token>
- Content-Type: application/json
Body:
["Java", "Spring Boot", "Docker"]
Response JSON:
["Docker", "Java", "Spring Boot"]

4) Remove a skill (DELETE)
URL: /api/users/me/skills/{skillName}
Example: /api/users/me/skills/Spring Boot
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON:
["Docker", "Java"]

5) Delete my account (DELETE)
URL: /api/users/me
Headers:
- Authorization: Bearer <token>
Body: (none)
Notes:
- Returns 400 Bad Request if you still own projects (delete/transfer them first).

PROJECTS
1) Create project (POST)
URL: /api/projects
Headers:
- Authorization: Bearer <token>
- Content-Type: application/json
Body:
{
  "title": "AI roadmap tool",
  "description": "Seeking backend + data folks",
  "teamSizeNeeded": 5,
  "requiredSkills": ["Java", "Spring Boot", "PostgreSQL", "Docker"]
}
Response JSON (example):
{
  "id": 8,
  "title": "AI roadmap tool",
  "description": "Seeking backend + data folks",
  "status": "RECRUITING",
  "owner": { "id": 3 },
  "applications": [],
  "teamSizeNeeded": 5,
  "requiredSkills": ["Java", "Spring Boot", "PostgreSQL", "Docker"],
  "rolesNeeded": [],
  "members": []
}

2) List all projects (GET)
URL: /api/projects
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON (example):
[
  {
    "id": 8,
    "title": "AI roadmap tool",
    "description": "Seeking backend + data folks",
    "status": "RECRUITING",
    "teamSizeNeeded": 5,
    "requiredSkills": ["Java","Spring Boot","PostgreSQL","Docker"],
    "owner": { "id": 3, "username": "pepsi" },
    "membersCount": 1
  }
]

3) List available projects (GET)
URL: /api/projects/available
Headers:
- Authorization: Bearer <token>
Body: (none)
Notes:
- Returns only projects with status=RECRUITING and not full (membersCount < teamSizeNeeded, or teamSizeNeeded <= 0).
Response JSON matches the format shown above for project summaries.

4) View project team (GET) - owner only
URL: /api/projects/{projectId}/team
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON:
[
  { "id": 12, "username": "pepsi", "email": "pepsi@max" }
]

APPLICATIONS
1) Apply to project (POST)
URL: /api/applications/apply/project/{projectId}
Headers:
- Authorization: Bearer <token>
Body: (none)
Response: "Application submitted successfully!"
Notes:
- Returns 400 Bad Request with "You have already applied to this project." if the same user applies twice.

2) List applications for your project (GET) - owner only
URL: /api/applications/for-project/{projectId}
Headers:
- Authorization: Bearer <token>
Body: (none)
Response JSON (example) – includes applicant details and skills:
[
  {
    "id": 25,
    "status": "PENDING",
    "appliedAt": "2025-11-11T15:30:12.345Z",
    "applicant": {
      "id": 12,
      "username": "pepsi",
      "email": "pepsi@max",
      "skills": ["Docker","Java","Spring Boot"]
    }
  }
]

3) Update application status (PATCH) - owner only
URL: /api/applications/{applicationId}/status
Headers:
- Authorization: Bearer <token>
- Content-Type: text/plain
Body (raw, not JSON):
ACCEPTED
or
REJECTED
Effects:
- ACCEPTED adds applicant to project members, sends email to applicant
- REJECTED sends email to applicant
Response JSON (example) – echoes the updated application with applicant details:
{
  "id": 25,
  "status": "ACCEPTED",
  "appliedAt": "2025-11-11T15:30:12.345Z",
  "applicant": {
    "id": 12,
    "username": "pepsi",
    "email": "pepsi@max",
    "skills": ["Docker","Java","Spring Boot"]
  }
}

EMAIL BEHAVIOR
- Registration sends verification email (From = spring.mail.username)
- Accept/Reject sends application status update email

TROUBLESHOOTING
- 401 Unauthorized: Missing/invalid JWT or login required
- 403 Forbidden: Not the project owner for this action
- 400 Bad Request: Invalid token/status/body or validation error
